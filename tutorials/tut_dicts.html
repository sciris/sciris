Dictionaries and dataframes

Needing a better way of ordering dictionaries was one of the original inspirations for Sciris back in 2014. In those dark days of Python <=3.6, dictionaries were unordered, which meant that dict.keys() could give you anything. (And you still can’t do dict.keys()[0], much less dict[0]). This tutorial describes sc.obj, Sciris’ dict that is also an object, and its pandas-powered pseudorelative, sc.dataframe.

sc.obj

In basically every situation except one, an sc.obj can be used like a dict. (Since this is a tutorial, see if you can intuit what that one situation is!) For example, creating an sc.obj works just like creating a regular dict:

import sciris as sc

ob = sc.obj(a=['some', 'strings'], b=[1,2,3])
print(ob)
sc.obj(a=['some', 'strings'], b=[1, 2, 3])

And it is one:

print(isinstance(ob, dict))
print(f'Keys:   {ob.keys()}')
print(f'Values: {ob.values()}')
print(f'Items:  {ob.items()}')
True
Keys:   ['a', 'b']
Values: [['some', 'strings'], [1, 2, 3]]
Items:  [('a', ['some', 'strings']), ('b', [1, 2, 3])]

Looks pretty much the same as a regular dict, except that ob.keys() returns a regular list (so, yes, you can do ob.keys()[0]).

When you’re just writing throwaway analysis code, it can be a pain to type mydict['key1']['key2'] over and over. (Right-pinky overuse is a real medical issue.) With an sc.obj, keys and attributes are the same thing, so you can use “object syntax” (a.b) instead of “dict syntax” (a['b']). This is especially handy for using f-strings, since you don’t have to worry about nested quotes:

print(f'Checking {ob.a = }')
print(f'Checking {ob["a"] = }') # We need to use double-quotes inside since single quotes are taken!

ob.c = 'a new key'
print(ob.keys())
Checking ob.a = ['some', 'strings']
Checking ob["a"] = ['some', 'strings']
['a', 'b', 'c']

You can also do things you can’t do with a regular dict, such as:

for i,k,v in ob.enumitems():
    print(f'Item {i} is called {k} and has value {v}')
Item 0 is called a and has value ['some', 'strings']
Item 1 is called b and has value [1, 2, 3]
Item 2 is called c and has value a new key

We can, as you probably guessed, also retrieve items by index as well:

print(ob['a'])
print(ob[0])
['some', 'strings']
['some', 'strings']

Remember the question about the situation where you wouldn’t use an sc.obj? The answer is if your dict has integer keys, then although you still could use an sc.obj, it’s probably best to use a regular dict. But even float keys are fine to use (if somewhat strange).

For example, let’s say we want to store a number of named simulation results. Look at how we’re able to leverage sc.obj in the loop that creates the plots:

import numpy as np
import matplotlib.pyplot as plt

class Sim:
    def __init__(self, n=20, n_factors=6):
        self.results = sc.obj()
        self.n = n
        self.n_factors = n_factors
    
    def run(self):
        for i in range(self.n_factors):
            label = f'y = N^{i+1}'
            result = np.random.randn(self.n)**(i+1)
            self.results[label] = result
    
    def plot(self):
        with sc.options.context(jupyter=True): # Jupyter-optimized plotting
            plt.figure()
            rows,cols = sc.getrowscols(len(self.results))
            for i,label,result in self.results.enumitems(): # sc.obj magic!
                plt.subplot(rows, cols, i+1)
                plt.scatter(np.arange(self.n), result, c=result, cmap='parula')
                plt.title(label)
            sc.figlayout() # Trim whitespace from the figure

sim = Sim()
sim.run()
sim.plot()

This is a have-your-cake-and-eat-it-too situation: the first set of results is correctly labeled (sim.results['y = N^1']), but you can easily access it without having to type all that (sim.results[0]).

Keys and methods

What if a key has the same name as a method? Methods are protected, so the method keeps working, and you get the key using dict syntax:

rates = sc.obj(infect=0.3, clear=0.1)
print(rates['clear'])
rates.clear()
print(rates)
0.1
sc.obj()

This matters if your keys come from somewhere else, such as a data file, since you don’t have to worry about one of them being called clear or pop. Trying to set rates.clear = 0.1 raises an error; rates['clear'] = 0.1 is fine.

Performance

sc.obj is about as fast as a plain Python object, and nearly as fast as a plain dict. Approximate times per operation, in nanoseconds:

ob['a'] ob.a ob['a'] = 1 ob.a = 1 Create
dict 10 n/a 15 n/a 50
sc.obj 20 15 15 20 300
sc.objdict 40 50 120 240 650

These differences won’t matter unless you’re doing millions of operations. But if you’re reading this, chances are high that you do sometimes need to do millions of dict operations, so it’s nice not to have to choose between speed and convenience.

Other dicts

Sciris has three other dicts, for less common needs:

  • sc.objdict is a slower version of sc.obj with a few more features: setting items by position (ob[0] = 3), getting them with a list of keys (ob[['a','b']]), and default values (defaultdict).
  • sc.odict is like sc.objdict, but with dict syntax only, and more verbose output for storing large(ish) objects.
  • sc.dictobj is a simpler dict with object syntax, without the methods or indexing of sc.obj, and a key can replace a method of the same name.

You can also subclass sc.obj; see its documentation for how to add attributes that aren’t keys.

Dataframes

The Sciris sc.dataframe() works exactly like pandas pd.DataFrame(), with a couple extra features, mostly to do with creation, indexing, and manipulation.

Dataframe creation

Any valid pandas dataframe initialization works exactly the same in Sciris. However, Sciris is a bit more flexible about how you can create the dataframe, again optimized for letting you make them quickly with minimal code. For example:

import pandas as pd

x = ['a','b','c']
y = [1, 2, 3]
z = [1, 0, 1]

df = pd.DataFrame(dict(x=x, y=y, z=z)) # Pandas
df = sc.dataframe(x=x, y=y, z=z) # Sciris

It’s not a huge difference, but the Sciris one is shorter. Sciris also makes it easier to define types on dataframe creation:

df = sc.dataframe(x=x, y=y, z=z, dtypes=[str, float, bool])
print(df)
   x    y      z
0  a  1.0   True
1  b  2.0  False
2  c  3.0   True

You can also define data types along with the columns:

columns = dict(x=str, y=float, z=bool)
data = [
    ['a', 1, 1],
    ['b', 2, 0],
    ['c', 3, 1],
]
df = sc.dataframe(columns=columns, data=data)
df.disp()
   x    y      z
0  a  1.0   True
1  b  2.0  False
2  c  3.0   True

Dataframe indexing

All the regular pandas methods (df['mycol'], df.mycol, df.loc, df.iloc, etc.) work exactly the same. But Sciris gives additional options for indexing. Specifically, getitem commands (what happens under the hood when you call df[thing]) will first try the standard pandas getitem, but then fall back to iloc if that fails. For example:

df = sc.dataframe(
    x      = [1,   2,  3], 
    values = [45, 23, 37], 
    valid  = [1,   0,  1]
)

sc.heading('Regular pandas indexing')
print(df['values',1])

sc.heading('Pandas-like iloc indexing')
print(df.iloc[1])

sc.heading('Automatic iloc indexing')
print(df[1]) # Would be a KeyError in regular pandas

Dataframe manipulation

One quirk of pandas dataframes is that almost every operation creates a copy rather than modifies the original dataframe in-place (leading to the infamous SettingWithCopyWarning.) This is extremely helpful, and yet, sometimes you do want to modify a dataframe in place. For example, to append a row:

# Create the dataframe
df = sc.dataframe(
    x = ['a','b','c'],
    y = [1, 2, 3],
    z = [1, 0, 1],
)

# Define the new row
newrow = ['d', 4, 0]

# Append it in-place
df.appendrow(newrow)

# Show the result
print(df)
   x  y  z
0  a  1  1
1  b  2  0
2  c  3  1
3  d  4  0

That was easy! For reference, here’s the pandas equivalent (since append was deprecated):

# Convert to a vanilla dataframe
pdf = df.to_pandas() 

# Define the new row
newrow = ['e', 5, 1]

# Append it
pdf = pd.concat([pdf, pd.DataFrame([newrow], columns=pdf.columns)])

That’s rather a pain to type, and if you mess up (e.g. type newrow instead of [newrow]), in some cases it won’t even fail, just give you the wrong result! Crikey.

Just like how sc.cat() will take anything vaguely arrayish and turn it into an actual array, sc.dataframe.cat() will do the same thing:

df = sc.dataframe.cat(
    sc.dataframe(x=['a','b'], y=[1,2]), # Actual dataframe
    dict(x=['c','d'], y=[3,4]),         # Dict of data
    [['e',5], ['f', 6]],                # Or just the data!
)
print(df)

0  a  1
1  b  2
2  c  3
3  d  4
4  e  5
5  f  6
